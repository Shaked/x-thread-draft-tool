# Media Attachments

- Attach up to 4 images per post.
- Image handling for draft composition flows.
- Uploads go to `/api/images?draftId=...` as raw bytes (4 MB maximum) and are stored in Vercel Blob under `drafts/<user>/<draft>/`.
- Publishing or deleting a draft deletes its Blob images.
- Media-aware publish/archive behavior.
- Image edits over REST and MCP (#412): `POST /api/drafts/:id/images` adds an image from a URL to a post at a place, or replaces one (`replace`); `POST .../posts/:postId/move` with `image_url` moves one; `DELETE /api/drafts/:id/images` removes one or all of a post. At most 4 per post; files no draft uses are deleted; a failed add deletes the new file. The editor has no image reorder or replace. Tool text (#414): `add_image_from_url` says `postId` adds the image to the post; `move_post` moves an image too; `remove_image` removes all of a post's images.
- Safe uploads (#416): on every upload route the type comes from the first bytes (PNG, JPEG, WebP, GIF), the `Content-Type` header is ignored, SVG and anything else is refused with a 415 that names the types that work. EXIF, XMP and text chunks are removed in plain JS (JPEG keeps only Orientation). Each stored file is counted per user in `image_files`; the admin user page and `admin_get_user` show `stored_bytes`. Files uploaded before this change are not counted (no backfill). No storage cap yet (owner question Q2 on #273).
- Image bytes for the tool (#419, plan 4.4): `add_image_from_url` takes `data` (base64, at most 933,336 characters = 700,000 bytes, checked before decoding) and `mime` instead of `url`; bad base64, a mime that differs from the bytes, or `url` and `data` together are refused before any upload. Same checks as `POST /api/images`. For our view and scripts; Claude Code uses `POST /api/images` with `curl --data-binary`.
- Chat-only image error (#415, plan 4.1): when `add_image_from_url` gets a `url` that does not parse as http(s) (a `data:` URL, a file path, an attachment name, `ftp:`, `file:`, `javascript:`, `blob:`), it uploads nothing and answers with the next step: the upload link first (with `postId`, `upload_link: true` and no `url`), then the editor link and the post number for the user. Without `postId` it names the editor link and "the post"; with `replace` it names the editor link only, since an upload link cannot replace an image. The editor link is built from a draft the caller owns. The check uses the same URL parser as the server fetch, so a leading space, `https:host/x.png` or backslashes count as http(s) and reach the server; credentials and private addresses are still refused by the server before any fetch.
- One-time upload link (#418, plan 4.2): `add_image_from_url` with `upload_link: true` and `postId`, or `POST /api/drafts/:id/posts/:postId/upload-links`, makes a link `/upload#<token>` for the free slots of one post (30 minutes, 10 links per hour). Only the token's hash is stored (`image_upload_links`). The page needs no sign-in, shows only the post number, the free slots and its own thumbnails, and sends the token as a bearer token to `POST /api/upload-links/images` (same checks as `POST /api/images`). A slot is claimed in one statement and given back if the upload fails; a dead link answers 410. `/upload` sends `Referrer-Policy: no-referrer`.
- "Add image" in the thread view (#420, plan 4.3): under each saved post with fewer than 4 images, when the host can call tools (`canCallTools()`). The view shrinks the chosen file on a canvas (at most 1600 px on the longer side, JPEG, under 933,336 base64 characters) and asks the host to call `add_image_from_url` with `draftId`, `postId`, `data` and `mime`. The answer's draft outline gives the post's new image count, which the view shows ("Images: 3"); the thumbnails are not redrawn. If the file input, the resize or the call fails, is refused, times out (120 s) or answers without that outline, it asks for `upload_link: true` and shows the link as text. After a timeout the first call may still finish, so the post can end with an extra image. English and Hebrew labels. The view stays under 32 KB: `pageScript` also drops comments inside functions and some spaces, and leaves strings and regex literals alone (no behavior change).
