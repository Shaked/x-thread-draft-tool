# Platform and Auth

- PWA support.
- Mobile-responsive UI.
- GitHub OAuth sign-in (`/api/auth/login`, `/api/auth/callback`). Anyone with a GitHub account can sign in.
- Session: signed HS256 cookie `xt_session` (HttpOnly, Secure, SameSite=Lax, 30 days). The GitHub token is not stored.
- View as a user, server core (#289): a signed `xt_view_as` cookie (audience `view-as`, 30 minutes, HttpOnly, Secure, SameSite=Strict) makes `authenticate` return the target user with `viewAs` set, only for the admin's own browser session (claim `admin_uid` and `admin_jti` equal the session's, admin role, target present, not suspended, not admin or CI). Bearer tokens, MCP, `readSession`, `realSession` and `/admin/*` never apply it. Every write as the target answers 403, `/tokens` and `/grants` answer 403, `/oauth/authorize` answers 409, logout clears both cookies. The admin cannot read drafts while viewing: the list shows counts under "Private draft" and opening a draft, its export and its history answer 403 "Viewing as cannot open drafts.", and the outline answers counts with no preview, no post text and no image urls (#385; one helper, `redactForViewAs` in `server/view-as-redact.js`, decides it and `tests/api/view-as-private.test.js` asserts every GET route under `/drafts` calls it). The draft list and the editor route show a lock and "Drafts are private. Viewing as shows counts only."; the editor is not mounted, so no draft is asked for. Image files are not fetchable for the target: no route serves them and no answer returns their urls. The admin user page has a View as button (a reason of 3 to 200 characters is required); on success the browser loads `/` afresh. While viewing, every page shows a fixed bar "Viewing as <login> · read-only · ends <time>" with Cancel (`DELETE /api/admin/view-as`, then a full page load of `/admin/users/<id>`; on a failure the bar shows the reason and stays). A timer does the same at `expires_at`, never sooner than 15 seconds after load. Controls that create, change or share are disabled with "Not available while viewing as <login>" (`disabledReason`), the editor writes nothing to this browser's storage and does not autosave, and Cancel or expiry never clears the admin's own cached drafts (#291).
- Role (#282): `GET /api/auth/me` returns `user.role` (`admin` or `user`) for a browser session, decided by `roleOf` in `server/admin/role.js`. API token callers get no role. The app shows an "Admin" badge next to the menu button and, in the app menu, one "Admin" link to `/admin` only for `admin` (#551). Nothing else of the admin is in the app menu: the changelog, the flags and the metrics are reached from the admin menu inside `/admin`.
- Owner-only writes are filtered by the session user id in every query; a non-owner gets 404.
- Deployment metadata visibility.
- API tokens page (`/settings/tokens`): create and revoke tokens.
- Feature flags page (`/admin/flags`, admin only since #483; `/settings/flags` and its menu entry are gone): two switches (#406, approved by Shaked 2026-11-25; real components asked for 2026-11-26). They are saved on the admin's own account (`users.ui_flags`, `GET` and `POST /api/admin/flags`, tools `admin_list_flags` and `admin_set_flag`, one audit row `set_flag` per change, no confirm token because only the admin's own view changes) and copied to the device for the first paint. The purple look and the plain components are the default for everyone (#406, owner decision 2026-11-27): for every other user a stored `xt-skin` or `xt-kit` is ignored, and the look and the components are always the default (`allowFlags` in `src/utils/skin.js`). Rare UI stays behind these switches, for the admin only: the account row stores a choice only when the admin sets it, so an admin who chose Rare UI explicitly keeps it and everyone else gets purple. Look: the purple look (default, labelled "Purple (everyone)") or the Rare UI look (labelled "Rare UI (only you)"; the components switch is "Plain components (everyone)" or "Rare UI components (only you)"); it sets `data-skin` on `<html>` from `xt-skin` in localStorage, and `src/styles/tokens.css` overrides tokens only, so every page and `src/ui/` component follows; colour contrast is tested for both looks. Components: the real Rare UI components (admin opt-in), copied into `src/ui/rare/` under their licence (MIT with Commons Clause and an attribution clause, `THIRD_PARTY_LICENSES/rare-ui.md`), replace the theme choice in the menu, Delete draft in the list, the post character counter and the toasts (copy, share and publish messages) (`xt-kit` in localStorage, read by `src/ui/ThemePicker.jsx`, `src/ui/DeleteButton.jsx`, `src/ui/Count.jsx` and `src/ui/Toast.jsx`). They use Tailwind utilities that take only token values, so they follow the look and the theme. The credit the licence requires: the About page (`/about`, signed in) has a Credits section with an English and a Hebrew line (`lang="he" dir="rtl"`), each with a link to https://rareui.com (the Hebrew link is `dir="ltr"` and `nowrap`, so it stays on one line; `src/pages/AboutPage.jsx`, unit test in `tests/unit/AboutPage.test.jsx`); `/admin/flags` keeps its own link.
- Connected apps page (`/settings/apps`): "Connect an AI app" lists the four clients with copy buttons; "Connected apps" lists and revokes them.
- Suspension: a suspended account is refused on every sign-in path (cookie, `xt_` and `xta_` tokens, MCP, the OAuth token endpoint, device sign-in, the GitHub callback, the CI identity). The API answers 403 "This account is suspended."; the app shows that notice above the sign-in button (`/?suspended=1`); share links of the account's drafts answer 410 and are not used up. Nothing is deleted, and everything works again after the suspension is lifted.
- Admin area (`/admin`, #285): a lazy chunk (`AdminLayout-*.js`, not precached) that only the admin's browser asks for. A menu (side column from 768 px, two columns above the page on phones; rows start-aligned and the open page marked, #551) with Statistics, Metrics, Feature flags, Changelog, Users and Audit log; Statistics, Metrics (#337: window switch, summary, a requests and p95 line chart in inline SVG, tables by route and tool, a product table), Feature flags (`/admin/flags`, #483) and Changelog (`/admin/changelog`, #484) are built, the others show "Coming soon.". Anyone else is sent to `/`, the same as an unknown path. When a lazy file fails to load (after a deploy the file of the build before is gone, and Vercel answers it with `index.html`), `src/ui/LoadBoundary.jsx` shows a notice with a Reload button instead of an empty page; the Rare UI components fall back to the current ones (#551, `tests/e2e/load-failure.spec.ts`).
- MCP connector at `/api/mcp` (OAuth 2.1 with PKCE, rotating refresh tokens). Setup and tools: [docs/agents/mcp.md](../agents/mcp.md); Hebrew setup: [docs/agents/mcp.he.md](../agents/mcp.he.md).

The MCP connector also offers four slash commands (prompts): `thread_from_notes`, `tighten_draft`, `review_before_publish` and `rewrite_hook`. It serves one skill, `x-thread-drafts` (at `skill://x-thread-drafts/SKILL.md`). Some tools also show a small view inside Claude or ChatGPT: the thread, the drafts list and the share card ([views](../agents/mcp.md#views-in-claude-and-chatgpt)). The labels and buttons of the three views are in English and Hebrew (#371): the view uses the host's locale when the host sends one, else the main script of the draft text, else English; in Hebrew the page is right to left and post text keeps its own direction. Requests may be in Hebrew (עברית), using words such as טיוטה (draft), שרשור (thread) and ציוץ (tweet). X and Twitter (X/טוויטר) are the same service. Publishing a draft in this app posts nothing to X/Twitter.
