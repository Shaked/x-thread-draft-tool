# Authorization server endpoints (plan 7.5)

- Metadata: `GET /.well-known/oauth-protected-resource` and `.../api/mcp` (RFC 9728, resource `<origin>/api/mcp`), `GET /.well-known/oauth-authorization-server` (RFC 8414, with `code_challenge_methods_supported: ["S256"]`, `client_id_metadata_document_supported`, `authorization_response_iss_parameter_supported`). `vercel.json` rewrites `/.well-known/*` to the API handler.
- Client registration: `POST /api/oauth/register` (RFC 7591, public clients only). Client ID Metadata Documents: an https `client_id` is fetched once and cached (at most 24 h, honouring `Cache-Control` `no-store`/`no-cache`/`max-age`). The fetch refuses private addresses, redirects, non-JSON, documents over 10 KB and a mismatched `client_id`.
- Authorize: `GET /api/oauth/authorize` requires PKCE S256 and a `resource` (`/api/mcp` by default, or `/api`). An unknown client or an unregistered redirect URI gets an error page, never a redirect. Other problems redirect with `error`, `state` and `iss`. Signed out users go through GitHub sign-in and come back (`/api/auth/login?return_to=` accepts only `/api/oauth/authorize?...`). The consent page is plain HTML with a signed 10-minute decision. `POST /api/oauth/authorize` checks that the decision belongs to the signed-in user (403 otherwise).
- Token: `POST /api/oauth/token` for `authorization_code` (single use; a second use revokes the grant; client, redirect URI, PKCE and resource must match) and `refresh_token` (rotation from the 7.4 token service).
- Revoke: `POST /api/oauth/revoke` (RFC 7009) revokes the token's grant and always answers 200.
- Router: the Origin check is skipped for `POST /oauth/token`, `/oauth/register` and `/oauth/revoke`, which use no cookies. `/oauth/authorize` keeps the check.
- OpenAPI documents every new route. Existing endpoints are unchanged.
- Tests: `tests/api/oauth.test.js` (42 tests) covers metadata, registration validation, metadata-document clients (private address, http, mismatched id, over 10 KB, redirect, caching), authorize (unknown client, redirect URI mismatch, missing PKCE, unknown resource, sign-in return path, consent headers and escaping), consent POST (other user, tampered decision, deny, cross-origin), token (happy path, PKCE mismatch, redirect mismatch, resource mismatch, expired code, code reuse, refresh rotation and reuse, client mismatch), revoke, and the `return_to` allow-list.
