# Light default and Light / Dark / Match device setting (plan Task 6.2)

- The app now starts in light. `:root` holds the light tokens; `:root[data-theme="dark"]` and `:root[data-theme="system"]` (under `prefers-color-scheme: dark`) hold the dark ones.
- `index.html` sets `data-theme` from `localStorage['xt-theme']` before the first paint (light when missing or invalid, inside try/catch). It also sets the color-scheme and theme-color meta tags. The PWA manifest's `theme_color` is now `#ffffff`, matching `background_color`.
- `src/utils/theme.js`: `getTheme`, `setTheme`, `applyTheme`, `resolvedTheme`. Storage errors are ignored.
- `src/components/ThemeSetting.jsx`: a three-segment radio group ("Light", "Dark", "Match device"). Shown on the draft list header and on the settings (API tokens) page.
- The emoji picker and the tweet embed use the resolved theme instead of hard-coded light.
- Contrast: the light palette follows the plan, with three values changed to pass the contrast test: accent `#1670ad` (white text on `#1d9bf0` was 3.0:1), danger `#c4161f`, and border `#7b8a96` (3:1 against white). The dark theme also changes, to pass the same test: accent text is black (`#000`, was white at 3.0:1) and the border is `#5c6670` (was `#333`, 1.7:1).
- Tests: `tests/unit/theme.test.js` (default, persistence, invalid value, `system` via matchMedia, blocked storage) and `tests/unit/contrast.test.js` (WCAG pairs from the plan, both themes, values read from `App.css`).
- Checked: the light editor at 1280 px and the dark draft list (stored choice Dark, applied on load).
