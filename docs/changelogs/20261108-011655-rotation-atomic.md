# Atomic refresh-token rotation

- `server/db.js` gains `transaction(fn)`: BEGIN, run `fn` with a `q(text, params)` that must be used for every statement inside it, COMMIT; on error ROLLBACK and rethrow. Production checks out the pool's single client for the duration. `query()` behaves as before.
- `rotate()` (`server/oauth/tokens.js`) now spends the refresh token and inserts its replacement pair, and updates `last_used_at`, in one transaction. If any statement fails, the rollback leaves the original refresh token unspent, so a retry works. Reuse detection still revokes the grant when the spend finds the token already used.
- Cleanup of expired tokens is best effort and runs after the transaction commits. Its failure is logged (`[oauth] token cleanup failed`) and never thrown, and it cannot change whether rotation succeeded or whether the grant is revoked. The delete only matches rows past their expiry, so re-running it is harmless.
- `issuePair()` keeps its behaviour (insert, then best-effort cleanup).
- Tests: `tests/api/oauth-tokens.test.js` covers a failing replacement insert (original token stays usable, grant not revoked), a failing last-used update (spend rolled back), a failing cleanup (rotation still returns the new pair, no revocation), and reuse after a rotation with failing cleanup.
