# OAuth review fixes (PR #50)

- Re-approving a revoked app no longer revives its old tokens. In one transaction, approval locks the grant row, deletes the grant's existing codes and tokens when it was revoked, then reactivates it and issues the new code. Unused codes from before the revocation are refused.
- Code exchange is atomic. Spending the code, inserting the token pair and stamping `last_used_at` run in one `transaction()`. A failed insert rolls back, so the code stays unused and the grant is not revoked; a retry succeeds. Reuse of a spent code still revokes the grant. Cleanup of expired tokens stays outside the transaction and is best effort.
- `server/oauth/tokens.js` exports `insertPair` and `cleanupExpired` for the route's transaction.
- Tests: `tests/api/oauth.test.js` adds three regression tests (re-approval refuses old tokens, pre-revocation code refused, failed insert rolls back and retry succeeds).
