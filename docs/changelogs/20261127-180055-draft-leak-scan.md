# Draft text stays out of logs and admin views

- A new test fails if draft text shows up in logs, in another user's answers, in admin answers or in the wrong tables.
- No change for people using the app.

Area: Security
Link: https://github.com/Shaked/x-thread-draft-tool/pull/614

## Technical details

`tests/api/plaintext-leak-scan.test.js` (plan H10, #384). Fake data only. One exception is named in the test: the owner's own draft in the 412 stale-save answer.

The scan found one leak: an unhandled error was logged with its message, which can echo draft text. Errors now go through `server/log-error.js`, which logs the name, code and stack frames, not the message. The router and the two MCP error sites use it.

The scan also checks every `/admin` route the router has, user B's statuses, and the stale-save answer for its owner only.
