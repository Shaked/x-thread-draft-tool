# Friendlier editor UI (plan Task 6.3a)

Screen group: the draft editor (`DraftEditor`, `ThreadComposer`, `PostBox`, `ImageUpload`, `EmojiPicker`). `CharacterCounter` is not imported anywhere, so it is unchanged.

Behaviour is unchanged: no API call, state or effect was touched. Changes are markup, labels and CSS.

## Other changes

- Phones (390 px): the editor actions (Share, Agent, X Thread, Publish, Logout) sit in a sticky bottom bar as text buttons. The header keeps Back, the title and the status.
- Touch targets: 44 × 44 px minimum for toolbar, post, image, carousel, header and embed controls.
- Body text is 16 px in the editor. Small meta text (counters, post number) is 14 px.
- Editor text is capped at 70ch.
- Focus ring: 2 px `var(--focus)` on `:focus-visible` inside the editor.
- The upload area opens with Enter or Space as well as a click.
- `.deployment-meta` is hidden on the editor page with `.app:has(.draft-editor)`. The banner still shows on other pages until 6.3d.
- No hard-coded colours. The Remove image and carousel arrow buttons now use `--bg` and `--border`, which keeps text readable in both themes.

## Known gaps

- The header status shows `Saving…` while a save is pending. A failed save also leaves it on `Saving…`, because `saveDraft` swallows the error and the UI keeps no error state. A calm sync-error message needs a state change, so it is left for a follow-up.
- Remove post and Remove image run without a confirmation. Adding one is a behaviour change, so it is left for a follow-up.
