# Device flow and scripts use the short-lived pair (plan 7.7)

- Device login issues a 1-hour `xta_` access token and a rotating `xtr_` refresh token. Each device name is a connected app. The flow no longer creates `xt_` tokens.
- `scripts/agent-credentials.mjs` saves the pair (mode 600), refreshes it under a lock, and `scripts/xt-token.mjs` prints a valid access token for smoke.
- Docs and OpenAPI updated; `scripts/smoke.mjs` accepts `oauth` auth; tests in `tests/api/device.test.js` and `tests/unit/agent-credentials.test.js`.
- Hand-made `xt_` tokens are unchanged here (the 7-day cap is task 7.9).
