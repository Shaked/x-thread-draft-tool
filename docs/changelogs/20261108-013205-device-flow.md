# Device flow and scripts use the short-lived pair (plan 7.7)

- `POST /api/auth/device/poll` returns 201 with `access_token` (`xta_`, 1 hour, bound to `<origin>/api`), `refresh_token` (`xtr_`, rotates), `token_type`, `expires_in`, `scope`, `client_id` and `user`. `token` remains as a deprecated alias of `access_token` for one release. It no longer creates an `xt_` token.
- Each device name is a connected app: `oauth_clients` `device:<name>` (kind `device`) and one grant per user and resource. Signing in again reuses an active grant; a revoked one is replaced, so its old tokens stay dead. Names are trimmed and limited to 100 characters.
- `scripts/agent-credentials.mjs` (new) holds the logic: device login, saving the pair to `~/.config/xt/credentials.json` (file 600, directory 700, or `XT_CREDENTIALS_FILE`), and refreshing the access token when it is within 60 seconds of expiry. Every refresh saves the rotated refresh token.
- `scripts/agent-login.mjs` saves that pair instead of `.xt-token`. The new `scripts/xt-token.mjs` prints a valid access token for `XT_TOKEN=$(node scripts/xt-token.mjs) npm run smoke`, and exits 1 with the `npm run agent:login` hint when it cannot.
- Docs: `docs/agents/api.md` (MCP connector first, device flow second, hand-made tokens last), `public/llms.txt`, `server/openapi.js`, `README.md`.
- Tests: `tests/api/device.test.js` covers the pair, REST access, refusal on `/api/mcp`, rotation with reuse revocation, a wrong client, re-login and revoked grants, and the name limit. `tests/unit/agent-credentials.test.js` covers the scripts with a mocked fetch: login with polling, file modes, fresh and expired tokens, the safety margin, rotation, a refused refresh, and the command's exit code.
- `scripts/smoke.mjs`: the "me" step accepts `auth: "oauth"` as well as `"token"`, because an access token reports `oauth`.
- Acceptance (local, `npm run dev:api -- --fake-github`): `agent-login` once, then `XT_TOKEN=$(node scripts/xt-token.mjs) smoke` passes 16/16, and again after the access token was forced to expire (refresh) passes 16/16.
- Hand-made `xt_` tokens are unchanged in this PR (the 7-day cap is task 7.9).
